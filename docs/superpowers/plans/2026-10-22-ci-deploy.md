# CI Deploys the App - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every push to `main` that passes `static`, `tests`, `rust` and `build` deploys the app Worker `map-factorygamefan-com`, with no person at a terminal.

**Architecture:** A `deploy` job at the end of `.github/workflows/verify.yml` builds `dist`, asks a small TypeScript gate (`scripts/deploy-gate.ts`) whether this commit should go live, runs the repo's pinned wrangler with a token held in a `main`-only GitHub environment, then proves the deploy with `verify:deploy`. Renovate stops automerging action digests, since a merge now ships with a secret.

**Tech Stack:** GitHub Actions, wrangler 4.151.1 (pinned in `preview-service/worker`), Node `.ts` scripts run directly (type stripping), `vite-plus/test`, `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-10-22-ci-deploy-and-container-removal-design.md`, section "Step 1: CI deploys the app". Steps 2 and 3 get their own plans.

## Global Constraints

- Trigger: `push` to `main` and `workflow_dispatch`; the job also requires `github.ref == 'refs/heads/main'`. Never `pull_request`.
- `needs: [static, tests, rust, build]`, with each `needs.*.result == 'success'` asserted explicitly.
- No deploy concurrency group. The gate decides (table in Task 1).
- Deploy command: `pnpm --filter @fmw/preview-worker exec wrangler deploy --cwd ../.. --strict --message "$GITHUB_SHA" --tag "${GITHUB_SHA::7}"`, in a plain `run:` step. No `cloudflare/wrangler-action`.
- `CLOUDFLARE_API_TOKEN` is an **environment** secret and `CLOUDFLARE_ACCOUNT_ID` an environment variable, both on environment `production`, whose deployment branches are `main` only. They appear only in the deploy step's `env`.
- Token (Eric creates it): account-owned, Workers `Editor` on `map-factorygamefan-com` only, expiry one year out. Add `Zone > Workers Routes > Write` on `factorygamefan.com` only if the first deploy fails on the custom domain.
- Actions pinned to a full SHA with `# vX.Y.Z`; `permissions: contents: read`; no `version:` on `pnpm/action-setup`; `node-version-file: .node-version`.
- The deploy job is NOT added to ruleset `EJ`.
- No em or en dashes in any file; prose at a 12th-grade level or below.
- Logic goes in `.ts` scripts, not inline shell. Plain `run:` lines in the YAML are fine.

## Review Focus

1. **The workflow merges before the environment exists.** GitHub then auto-creates `production` with no branch rule, and the protection is gone. Task 4 must land, and be read back, before Task 5's PR merges. Task 6 checks it again.
2. **A redeploy of the commit that is already live** (the dispatch button, or a re-run) must deploy, not skip. Pinned in Task 1.
3. **A `/version.json` with no `fullCommit`** (any field missing or `"unknown"`) must fail with a clear message, not crash. Pinned in Task 1.
4. **A live commit the checkout does not know** (git exits 128) must read as "not on main" and fail with the redeploy hint, not throw a stack trace. Pinned in Task 1.
5. **Edge propagation lag** makes the first `verify:deploy` see the old commit. The CI step retries; a local run's behavior is unchanged. Pinned in Task 2.

### Task 1: The deploy gate

**Files:**
- Create: `scripts/deploy-gate.ts`
- Test: `test/deployGate.spec.ts`

**Interfaces:**
- Consumes: `fetchLiveBuild(site)`, `DEFAULT_SITE` from `scripts/verify-deploy.ts`; `BuildInfo` type from `scripts/buildStamp.ts`.
- Produces:
  - `type Ancestry = "yes" | "no" | "unknown"`
  - `interface GateFacts { live: Partial<BuildInfo> | null; runSha: string; liveOnMain: Ancestry; liveBeforeRun: Ancestry; runBeforeLive: Ancestry }`
  - `type GateAction = "deploy" | "skip" | "fail"`
  - `function decideDeploy(f: GateFacts): { action: GateAction; lines: string[] }`
  - `function gitIsAncestor(a: string, b: string): Ancestry` (exit 0 -> "yes", 1 -> "no", anything else -> "unknown")
  - CLI: `node scripts/deploy-gate.ts` reads `GITHUB_SHA`, fetches the live stamp (`FMW_DEPLOY_URL` or `DEFAULT_SITE`), writes `action=<deploy|skip>` to `$GITHUB_OUTPUT`, prints `::warning::` on skip, `::error::` and exits 1 on fail.

The decision table, in this order (first match wins):

| condition | action | message must say |
| --- | --- | --- |
| `live === null` | fail | the stamp could not be read |
| `live.fullCommit` missing or `"unknown"` | fail | no commit in the live stamp |
| `live.dirty === true` | fail | live was deployed from a dirty tree; redeploy `main` |
| `liveOnMain !== "yes"` | fail | live commit is not on `main`; redeploy `main` with the dispatch button |
| `liveBeforeRun === "yes"` | deploy | (none needed) |
| `runBeforeLive === "yes"` | skip | a newer commit is already live, naming both |
| otherwise | fail | cannot order the two commits |

`gitIsAncestor(x, x)` is "yes", so a redeploy of the live commit deploys.

- [ ] **Step 1: Write the failing tests** in `test/deployGate.spec.ts`, one `it` per row plus the Review Focus cases. Build facts with a helper `facts(over: Partial<GateFacts>)` whose defaults are a clean normal case (`live: { fullCommit: "a".repeat(40), commit: "aaaaaaa", dirty: false }`, `runSha: "b".repeat(40)`, all three ancestries `"yes"`). Assert:
  - default -> `action === "deploy"`
  - `live: null` -> `"fail"`, and `lines.join("\n")` matches `/could not be read/i`
  - `live: { commit: "aaaaaaa" }` (no `fullCommit`) -> `"fail"`, `/no commit/i`
  - `live: { ...base, fullCommit: "unknown" }` -> `"fail"`
  - `live: { ...base, dirty: true }` -> `"fail"`, `/dirty/i` and `/redeploy/i`
  - `liveOnMain: "no"` -> `"fail"`, `/not on main/i` and `/dispatch/i`
  - `liveOnMain: "unknown"` -> `"fail"` (Review Focus 4)
  - `liveBeforeRun: "no", runBeforeLive: "yes"` -> `"skip"`, and the lines contain both 40-char SHAs
  - `liveBeforeRun: "no", runBeforeLive: "no"` -> `"fail"`
  - `runSha` equal to `live.fullCommit` with all ancestries `"yes"` -> `"deploy"` (Review Focus 2)
  - `gitIsAncestor("HEAD", "HEAD")` -> `"yes"`; `gitIsAncestor("HEAD", "0".repeat(40))` -> `"unknown"` (real git, this repo)

- [ ] **Step 2: Run them and see them fail**

Run: `pnpm vp test test/deployGate.spec.ts`
Expected: FAIL, cannot resolve `../scripts/deploy-gate`.

- [ ] **Step 3: Implement `scripts/deploy-gate.ts`**

`decideDeploy` is the table above. `gitIsAncestor` uses `execFileSync("git", ["merge-base", "--is-ancestor", a, b], { stdio: "ignore" })` and reads `err.status`. The CLI computes `liveOnMain = gitIsAncestor(live.fullCommit, "origin/main")`, `liveBeforeRun = gitIsAncestor(live.fullCommit, runSha)`, `runBeforeLive = gitIsAncestor(runSha, live.fullCommit)`, catches a `fetchLiveBuild` error into `live = null`, and uses the same "only run when executed directly" guard as `verify-deploy.ts`. Header comment: what it decides, the squash-merge reason for the off-main row (#434's `7711ad8`), and that it runs only in CI.

- [ ] **Step 4: Run the tests and see them pass**

Expected: PASS, 12 tests.

Expected: `action=deploy`. The live commit (`0294468` at the time of writing, or whatever `pnpm run verify:deploy` reports) is on `main` and is an ancestor of this branch.
